# Waveshare ESP32-C6-LCD-1.47

Независимая демка NaWServer для ESP32-C6FH4, 4 MB flash, LCD ST7789
172×320 и одного встроенного WS2812. Общий Vue frontend берётся из корня
репозитория; здесь хранится только профиль. HTTP/WS/SSE, CBOR со строковыми
ключами, задачи FreeRTOS, память и вычислительный эксперимент перенесены из
showcase в отдельное приложение с адаптером C6. Ядро NaWServer не изменяется.

## Сборка

Из корня репозитория:

```powershell
npm.cmd ci --no-audit --no-fund
npm.cmd run build:c6
Set-Location examples/c6_lcd147
go run ./tools/pack-assets/main.go
& "$env:USERPROFILE/.platformio/penv/Scripts/pio.exe" run -e c6 -j 8
```

ESP-IDF 5.5.6 / PlatformIO Espressif32 8.0.0, общий TCP-движок. Для Wi-Fi скопировать
`main/wifi_secret.example.hpp` в игнорируемый `main/wifi_secret.hpp`.
При первоначальной подготовке локально использована та же сеть, что у C3;
секреты в исходники и отчёты не включаются. Без credentials тест LCD работает,
но сетевое подключение не запускается. Обычная инициализация NVS; настройки
Wi-Fi из локального файла применяются через `WIFI_STORAGE_RAM`.

Перед прошивкой заново определить порт и убедиться в ESP32-C6 и ожидаемом MAC.
На 20.10.2026 проверен COM13, ESP32-C6FH4 rev 0.1, BASE MAC DEVICE-MAC.
COM-порт может измениться после переподключения. Загрузка:

Для встроенного USB Serial/JTAG задан `board_upload.before_reset=usb_reset`:
обычный reset у этой платы с esptool 4.5.1 возвращал wrong boot mode.

```powershell
& "$env:USERPROFILE/.platformio/penv/Scripts/pio.exe" run -e c6 -t upload --upload-port COM13
```

Разметка: NVS 0x9000..0xdfff, PHY 0xe000..0xefff, factory app
0x10000..0x30ffff. По прямому указанию владельца 20.10.2026 перед повторной
прошивкой полностью очищена flash C6. Автоматического стирания NVS при запуске,
форматирования файловой системы и OTA нет.
Команда upload пишет загрузчик, таблицу разделов и приложение; NVS не входит
в эти диапазоны. Бинарники, assets.hpp, dist и serial logs игнорируются.

## Проверка LCD

| Сигнал | GPIO |
|---|---:|
| MOSI | 6 |
| SCLK | 7 |
| CS | 14 |
| DC | 15 |
| RESET | 21 |
| Подсветка | 22 |
| SD CS, удерживается в 1 | 4 |
| WS2812, один светодиод, RMT | 8 |

LCD использует SPI2, 12 MHz, RGB565, смещение X=34. Инициализация адаптирована
из старого vendor-примера `ESP32-BLETPMS-and-more/Example/ESP32-C6-LCD-1.47-Test`.
Исправлена передача обоих байтов команды питания 0xd0. Все SPI операции
синхронные в отдельной задаче; буфер только 2752 байта. SD не монтируется.

Подсветка 30% (Waveshare рекомендует ≤50%). Каждые две секунды: красный,
зелёный, синий, белый, чёрный, затем сетка с цветными полосами, рамкой и
движущейся горизонтальной линией. Цикл повторяется каждые 12 секунд.
Состояние SPI и номер шаблона печатаются в USB serial. При ошибке запуска
LCD сетевое приложение продолжает запуск; при ошибке вывода подсветка гаснет.
Успешный SPI обмен не доказывает целостность шлейфа/матрицы: обратного чтения
LCD нет, итоговое изображение требуется проверить глазами на самой плате.

RGB работает только через RMT. SPI backend отклоняется, поскольку SPI2 занят
дисплеем. Число пикселей и список доступных драйверов приходят из устройства.
Для встроенного светодиода этой платы используется порядок каналов RGB:
при GRB владелец наблюдал перестановку красного и зелёного.
BLE, TPMS, SD, touch и OTA в этой заготовке не реализованы.

## Сетевые проверки

После получения реального IP из serial, из каталога демки:

```powershell
node ./tools/smoke.mjs http://DEVICE_IP
node ./tools/ui-smoke.mjs http://DEVICE_IP
```

Первый скрипт проверяет identity, telemetry, tasks, SHA256 встроенных ресурсов,
binary WS echo и SSE. Второй открывает headless Edge и сохраняет снимки общего
обзора и RGB в игнорируемый `local/`. Тестовые credentials защищённых операций:
`demo` / `showcase-only`, как в showcase. Настройка реальной авторизации остаётся
отдельной задачей. Для Vite dev C6 явно задать `NAWSERVER_C6_URL` адресом устройства;
автоматической подстановки адреса C3 для C6 нет.
