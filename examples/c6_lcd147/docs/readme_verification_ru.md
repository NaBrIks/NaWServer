# Проверка C6 — 20.10.2026

Плата: ESP32-C6FH4 rev 0.1, 4 MB flash, COM13, MAC DEVICE-MAC.
Перед записью chip/MAC проверялись через esptool. По прямому указанию владельца
выполнен полный `erase_flash`: success, 15.5 s. После этого обычная инициализация
NVS работает; временный обход NVS удалён. Другие платы не прошивались.

Конечная прошивка: PlatformIO Espressif32 6.10.0, ESP-IDF 5.4.0,
RISC-V GCC 14.2.0. Сборка и upload SUCCESS, hash flash verified.
RAM sections 72600 B, flash sections 1129677 B, firmware.bin 1130064 B.
SHA256: `96EFDCADCAF3DB720FABE045A05A3395A1D8849EED9892B4856A72C4081FAD02`.

Встроенный WS2812: один пиксель GPIO8 / RMT. После наблюдения владельца о
перестановке красного и зелёного порядок изменён GRB → RGB; конечный образ
перезалит. Физическое соответствие цветов после исправления требует проверки
владельцем. API передаёт GPIO8, count=1, available_drivers=[rmt].

LCD start ESP_OK, все шаблоны 0..5 передавались с SPI=ESP_OK, без перезапусков
в журнале успешного запуска. Подсветка 30%, SPI 12 MHz, 172×320, X offset 34.
Матрица повреждена по словам владельца; видимость изображения удалённо не
проверена. Успешная передача SPI не подтверждает исправность LCD.

Wi-Fi: одна начальная попытка с reason=201, повторное подключение успешно;
DHCP IP `192.0.2.1`, mask `255.255.240.0`, gateway `192.0.2.4`.
На конечной прошивке HTTP снова отвечает по этому адресу. Адрес не статический.
Ссылка http://192.0.2.1 зарегистрирована в локальный монитор стенда как отдельная демка,
репозиторий указан только в repositoryUrl.

Проверки:

- npm run build:c6: vue-tsc + Vite PASS; отдельный профиль общего frontend.
- npm test: 10/10 PASS, включая count=1/count=10 и отказ неверной длине pixels.
- tools/smoke.mjs на конечной прошивке: PASS identity C6, RAM/summary contract,
  один RGB, FreeRTOS tasks, SHA256 всех 5 вшитых ресурсов, CBOR binary WS echo
  с байтами 0/128/255, настоящий SSE diagnostic.
- tools/ui-smoke.mjs: PASS на настоящей плате: HTTP/WS/SSE одновременно,
  задачи, маркер C6, один RGB GPIO8, только RMT, нет JS errors.
- Снимки overview.png и rgb.png в игнорируемом local/ просмотрены: единый
  обзор CPU/RAM/задач и унаследованный общий экран управления RGB.

Edge в этой среде завершался с exit 21. Браузерная проверка выполнена через
установленный Chromium headless shell с C6_BROWSER_EXECUTABLE; прямой доступ
к LAN задан --no-proxy-server. Без него системный proxy мешал браузерному WS.
При необходимости TEMP/TMP задаются явно и должны быть доступны выбранному компилятору.

Секреты Wi-Fi, firmware, dist, assets.hpp, логи и снимки игнорируются Git.
BLE/SD/TPMS/touch/OTA, длительный soak, нагрузочный и физический цветовой тест
после RGB исправления в эту проверку не входят.

## Заливка принятого UI на C6, 20.10.2026

По прямому запросу владельца версия с восстановленными графиками INFO и единым
компактным CPU/MEM над правой таблицей задач залита на C6 / COM13.
Перед записью проверен ESP32-C6, MAC DEVICE-MAC.
RAM sections: 72608 B; flash sections: 1137955 B; firmware.bin: 1138352 B.
SHA256: C3EB3DBE6533AD9392AE08636750166D639A4EC7EFAF2123BE8EA6F0C0093C98.
Запись и hash verification SUCCESS. Полного стирания/NVS erase не выполнялось.

API smoke PASS: реальные C6 identity/details, RAM/задачи, SHA всех 5 ресурсов,
бинарный WS echo и SSE. Первый браузерный запуск и повторный HTTP запрос дали
таймаут; LCD продолжал работать по USB, ARP соответствовал нужному MAC.
После обычного USB-reset без изменения firmware плата повторно получила
192.0.2.1. При подключении были две попытки reason=201, затем успех.
Причина первоначального сетевого таймаута не установлена.

Реальный Chromium после reset: PASS HTTP/WS/SSE, INFO, один RGB GPIO8/RMT,
единый график над задачами, высота 74.25 px / строка 24.75 px, без текста осей,
все плотности, MAC/EUI и отсутствие JS errors. Финальный API read после
браузерной проверки снова подтвердил source=device и IP 192.0.2.1.
C3 и S3 не прошивались. Длительная стабильность сети этой проверкой не доказана.
