# Showcase: общие ресурсы, фиксированные шкалы и уведомления

Актуальное размещение задач и последняя прошивка — в
[отчёте о постоянной правой панели](readme_task_dock_ru.md). CPU и память остаются
в центральном обзоре; задачи теперь доступны рядом с ними и на остальных страницах.

Обновление 19.10.2026. Это текущее устройство страниц; раздельные «Обзор»,
«Задачи / CPU» и «Память» из прежних отчётов заменены одной страницей
**«CPU · Память · Задачи»** (`#overview`). Старые `#tasks` / `#memory` ведут сюда.

На одной странице сохранены:

- История загрузки CPU и свободной внутренней RAM.
- Все регионы памяти: полный объём, свободный объём, минимум с запуска,
  крупнейший свободный блок. Таблица использует КиБ с одним десятичным знаком;
  подсказки показывают точное число байт. Пересекающиеся регионы не суммируются.
- Все FreeRTOS-задачи, фильтр и сортировка кнопками. CPU показывается с одним
  десятичным знаком; приоритет, ядро и минимальный стек — целыми числами.
- Инспектор выбранной задачи: накопленный runtime, минимум стека, история CPU.
  При выборе инспектор прокручивается в видимую область; закрытие возвращает фокус.
- Паспорт устройства, версия прошивки и boot ID.

Числовые заголовки и значения выровнены вправо, используются табличные цифры.
Единицы находятся в заголовках столбцов. Числовые колонки имеют компактную
постоянную ширину; заголовки не обрезаются. Аналогичное выравнивание применено
к SSE-журналу и общей полосе.

Автошкалы удалены. CPU всегда 0–100%; память — от нуля до полного объёма
внутренней RAM из API. Одинаковый диапазон используется большим графиком и
мини-графиком в общей полосе. Изменение свободной памяти диапазон не меняет.
Другая ёмкость при смене модели/устройства является другим физическим диапазоном.

## Постоянная полоса и сообщения

Общая полоса CPU / RAM / uptime / задачи / WS / SSE RX / RSSI находится выше
заголовка страницы. Мини-графики показывают 60 секунд реальных принятых samples.
Сбой HTTP не скрывает ещё свежую телеметрию WS. После истечения 6 секунд значения
помечаются устаревшими, история остаётся видимой. До определения источника UI
показывает ожидание, не объявляет неизвестную плату симулятором.

Ошибки показываются фиксированным стеком справа снизу и не участвуют в раскладке.
Успех: зелёный / 3,5 с; информация: синий / 5 с; предупреждение: жёлтый / 8 с;
ошибка: красный / до ручного закрытия. Есть закрытие каждого сообщения и «Закрыть
все», индикация времени; наведение и клавиатурный фокус приостанавливают таймер.
Стек ограничен пятью сообщениями, одинаковые сообщения объединяются. Один сбой
HTTP не создаёт новое сообщение на каждом poll. Восстановление снимает сообщение
о сбое и показывает короткое подтверждение.

Остальные страницы имеют определённое назначение: «Соединения» содержит схему,
управление WS/SSE и счётчики; «События / SSE» — журнал; «Лаборатория» — echo;
«Эксперименты» — управление нагрузкой/RGB; «Доступ» — общие session-only credentials
и пробы авторизации; «Настройки» — оформление. Повторные схемы, формы credentials,
управление транспортами в настройках и повторная SSE-сводка на обзоре удалены.

## Проверки

- `npm run build`: vue-tsc и Vite production — PASS.
- `node tests/notifications-smoke.mjs`: таймауты, постоянные ошибки, дедупликация,
  пауза мышью/фокусом, ограничение стека, закрытие и освобождение таймера — PASS.
- CUA `runShellSmoke`: проверяет размещение полосы, отсутствие сдвига при
  настоящем HTTP 401, цвета/таймер, закрытие всех, Dark/EN и страницы оболочки.
- CUA `runResourcesSmoke`: проверяет общий экран, фиксированные диапазоны,
  физическую ёмкость пула, геометрию правых краёв всех числовых ячеек, полную
  видимость заголовков, фильтр/инспектор задач, WS и SSE.
- Обрыв сети .NET-модели на 8 секунд: warning и HTTP 503 отображаются в стеке;
  верхняя координата области данных до/после — 116,57 px, без сдвига.

Скриншоты/JSON/firmware остаются ignored в `local/`. Эти UI-проверки не являются
длительным тестом сети, worst-case стека или электрических сигналов GPIO.

## Окончательная C3

Перед записью заново проверены chip/MAC; записан только app0, vendor hash и
boot/IP — PASS. Firmware 1 038 608 bytes, `[0x10000,0x10d910)`, SHA-256
`77a5de00f073aaad3bba5bf1084598895f64f611145c66088f9d6c3e45547330`.
Bootloader, partition table, NVS и data не записывались, backup/erase-all не
выполнялись; COM10 освобождён.

`runResourcesSmoke`: **13 PASS на C3**, **13 PASS на .NET-модели**. Включены
измерение правого края текста каждой числовой ячейки/заголовка, отсутствие
обрезанных заголовков и горизонтального overflow при проверенной ширине окна,
инспектор httpd и продолжение WS/SSE. Найдено 11 настоящих задач; шкала RAM C3
зафиксирована на полном размере heap-пула 243,90234375 КиБ, модель — 320 КиБ.

37 модели; последующее объединение страниц проверено отдельным resource harness.
