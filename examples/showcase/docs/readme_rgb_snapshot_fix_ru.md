# RGB: блокировка управления при смене снимка задач

На реальной C3 воспроизведено: WS и SSE онлайн, HTTP показывается offline,
кнопки RGB и ползунок disabled, уведомление `HTTP 409`. Причина — вторая
страница `/api/v2/tasks` запрашивалась после обновления снимка FreeRTOS (1 Гц).
Ожидаемый `409 snapshot_changed` попадал в общий обработчик потери HTTP.

Теперь этот ответ при опросе задач сохраняет последний полный снимок и доступность
управления. Следующий опрос начинает чтение с offset=0. Частичные строки и история
не публикуются. Другие ошибки по-прежнему обрабатываются как ошибки HTTP.
Драйвер RMT и авторизация не изменены.

Проверки 2026-10-19:
- `node frontend/tests/task-snapshot-smoke.mjs` (из frontend: `node tests/task-snapshot-smoke.mjs`):
  исполняются production poll/tasks с ответом 409 на второй странице, следующим
  успешным опросом и настоящей ошибкой 500; PASS.
- `npm run build --prefix frontend`, C3 PlatformIO build: PASS.
- На C3 после прошивки: 16 проверок live-controls, включая power, brightness,
  все эффекты, период, цвет и readback десяти пикселей; WS/SSE онлайн; PASS.
- Возвращён исходный режим до диагностики: RGB enabled, rainbow, 49%, 1000 ms.
  Снимок: ignored `local/screenshots/c3-rgb-snapshot-fix.png`.

Прошивка 1 040 928 байт, SHA256
`001c1381400a914cd4750104bdea019aa2b283309bee35d757c26f2e14feb711`.
Свежая проверка chip/MAC перед записью, только app0 `[0x10000,0x10e220)`,
vendor hash и boot/IP PASS, COM10 освобождён. Другие разделы не записывались.

Readback подтверждает настройки и успешный RMT refresh. Видимое свечение
физической ленты удалённо не наблюдалось; отдельная аппаратная неисправность
этим тестом не исключается. Временные HTTP-ожидания при первом открытии также
наблюдаются и не относятся к обработке snapshot_changed.
