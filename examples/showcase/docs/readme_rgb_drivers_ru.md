# RGB: переключение RMT / SPI на работающей C3

В панели RGB две отдельные кнопки RMT и SPI. Подсветка кнопки показывает
фактически созданный драйвер из телеметрии. Во время смены отображается передача;
ошибка создания или вывода показывается явно. Apply не требуется.

При включении питания: RMT, RGB включён, solid `0xffa030`, яркость 20%,
период 1000 ms. Всегда десять WS2812 / GPIO2 / GRB. Выбор SPI не сохраняется
между перезапусками. Переход не требует перепрошивки или переподключения DIN.

HTTP POST `/api/v2/strip` принимает необязательный `driver: "rmt" | "spi"`.
Без поля текущий запрос драйвера сохраняется. Неизвестное значение даёт 400,
авторизация Basic сохраняется. CBOR ID: driver=126, requested_driver=127,
driver_error=128. GET, POST-ответ и summary возвращают эти поля; POST подтверждает
принятие команды, а driver в последующей телеметрии подтверждает переключение.

Единственный владелец led_strip_handle — output_worker. После синхронного refresh
он удаляет старый драйвер, создаёт выбранный и выводит текущий кадр. HTTPD не
выполняет переключение и не ждёт его завершения. При ошибке создания делается
попытка восстановить прежний драйвер; код ошибки остаётся доступен в телеметрии.
Состояния органов управления синхронизируются с подтверждёнными настройками, в том числе после перезапуска и команд другого клиента. Синхронизация не порождает обратных команд и не затирает ожидающую локальную команду. Проверено на двух окнах модели: SPI / 37% перешли во второе окно; затем восстановлены RMT / 20%.

RMT сохраняет прежние 10 MHz / 48 symbols / no DMA. SPI использует MOSI GPIO2,
SPI2_HOST с DMA, резервируя всю эту шину; другие GPIO для SPI не подключаются.

Проверки 2026-10-19:
- TypeScript/Vue production build и C3 PlatformIO build — PASS.
- Showcase.Tests: 48 проверок, включая старт RGB on/RMT, SPI/RMT, одинаковый
  кадр десяти пикселей и отклонение неизвестного драйвера — PASS.
- `rgb-drivers-ui-smoke.mjs`: десять переключений кнопками в модели — PASS.
- `rgb-driver-device-smoke.mjs`: десять настоящих переключений на C3 через
  защищённый API, driver/requested_driver совпадают, supported=true,
  driver_error пуст, enabled=true, count=10, boot_id не менялся — PASS.
  Исходный цвет и яркость сохранены. В этом прогоне исходная яркость была 0%,
  поэтому он подтверждает работу драйверов, но не видимое свечение.
- На C3 проверена кнопка SPI с фактическим readback. Во время браузерной проверки
  наблюдались параллельные изменения яркости/драйвера и временные HTTP/WS/SSE
  потери связи (RSSI до -89 dBm). Это не длительный сетевой soak.
- Окончательный UI: 16 live-controls и десять переключений драйвера в модели — PASS. На окончательной C3 пройдены десять шагов переключения кнопками с readback всех десяти ненулевых пикселей при 20%; заключительная проверка транспорта этого smoke завершилась ошибкой (SSE offline, WS онлайн). Отдельный повтор CLI после холодного старта истёк по HTTP timeout. Полного PASS для всего сетевого smoke окончательной сборки не заявляется. После теста RMT / enabled / solid / 20%.

Один горящий пиксель не доказывает ошибку счётчика (он равен 10). Первый пиксель
или соединение между первым и вторым могут перестать передавать данные дальше.
