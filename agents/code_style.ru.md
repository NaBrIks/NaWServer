# Стиль исходного кода

## Автоматическое форматирование

Использовать Uncrustify 0.83.0_f с корневым `uncrustify.cfg`.
Отступ — Tab шириной 4. Существующие однострочные `if` сохраняются,
многострочные не склеиваются, между проверками добавляется пустая строка.
Между определениями методов и функций оставлять одну пустую строку
(`nl_after_func_body = 2`: два перевода строки).
Для определений внутри класса и однострочных тел также заданы
`nl_after_func_body_class = 2` и `nl_after_func_body_one_liner = 2`.
Проверено на копии `MemoryExchange`: методы разделяются пустыми строками.
Ограничение Uncrustify 0.83.0_f: при раскрытии вложенного однострочного деструктора
`Reset` в `memory.cpp` пустая строка после него может появиться только на втором прогоне.
Проверены однострочный, многострочный и смешанный варианты `digit()` и оба
образца ниже; повторный прогон не меняет результат.

Из корня репозитория в PowerShell:

```powershell
.\uncrustify-check.cmd
.\uncrustify-apply.cmd
```

Первая команда только проверяет, вторая изменяет файлы.
Обе находят `git.exe` и `uncrustify.exe` через PATH; машинных путей в скриптах нет.
Обрабатываются только отслеживаемые Git файлы C/C++; удалённые файлы,
сгенерированные `assets.hpp` и каталоги vendor/third_party пропускаются.
Новые неотслеживаемые файлы не включаются. Коммиты не создаются.
Apply не создаёт резервных копий или MD5-файлов.
Корневая `.gitattributes` задаёт checkout собственного C/C++ с LF, в том числе
на Windows при `core.autocrlf=true`. Vendor/generated/fonts и `assets.hpp`
исключены и из этой политики, и из форматирования. Свежий checkout должен
проходить Check без предварительного Apply. Не нормализовать vendor-файлы массово.
Коды завершения: 0 — успех, 1 — отличия оформления при проверке или ошибки
обработки файлов, 2 — ошибка настройки/аргументов. Проверка продолжает работу
после отличий и выводит итоговое число ошибок.

Установить официальный Uncrustify 0.83.0_f и добавить его каталог в PATH.
После изменения PATH открыть новый
терминал; для встроенного терминала перезапустить редактор.
Не запускать apply без запроса владельца на форматирование исходников.

Прежние конфигурация и скрипты clang-format отложены в игнорируемый
`local/clang-format-archive/`. Они не активны и не включаются в Git. Для повторного
использования сначала вернуть их в корень: скрипты рассчитаны на запуск оттуда.
Пробные образцы и результаты остаются в игнорируемом `local/formatting-trial/`.

Прочитайте этот файл перед написанием или форматированием исходников. Примеры и
примечания задают оформление для указанного языка и области применения. Владелец
может менять исходные образцы; следуйте его правкам. Форматирование само по себе
не должно менять логику или имена. Не форматируйте весь репозиторий без явного запроса.

## Пример 1: объявления, классы и заголовки

Область применения: C++, объявления в заголовочных файлах проекта.

```cpp
#pragma once

#include <cstddef>
#include <cstdint>

namespace NaWServer
{

	// Буфер заимствуется и должен существовать дольше объекта.
	class MessageBuffer
	{
	public:
		MessageBuffer(std::uint8_t *storage, std::size_t capacity);

		bool append(const std::uint8_t *data, std::size_t size);
		std::size_t size() const;

	private:
		std::uint8_t *storage_;
		std::size_t capacity_;
		std::size_t size_ = 0;
	};

} // namespace NaWServer
```

Примечания (можно менять вместе с образцом):

- Отступ — символ Tab, отображаемый как 4 пробела. Пробелы допустимы для выравнивания внутри строки.
- Открывающая фигурная скобка — на новой строке; public/private на уровне скобок класса.
- Знаки указателя и ссылки — у имени: `const Request &request`, `std::uint8_t *data`.
- Не выравнивать объявления дополнительными пробелами в колонки.

## Пример 2: функции, условия и переносы строк

Область применения: C++, определения функций и управляющие конструкции.

```cpp
MessageBuffer::MessageBuffer(std::uint8_t *storage, std::size_t capacity)
  : storage_(storage), capacity_(capacity)
{
}

bool MessageBuffer::append(const std::uint8_t *data, std::size_t size)
{
	if(data == nullptr)
		return false;

	if(data == nullptr || storage_ == nullptr || size > capacity_ - size_)
	{
		return false;
	}

	for(std::size_t index = 0; index < size; ++index)
	{
		storage_[size_ + index] = data[index];
	}

	size_ += size;
	return true;
}

std::size_t MessageBuffer::size() const
{
	return size_;
}

// Перенос длинного вызова: по одному аргументу на строку.
const bool published = publish_device_status(
	device_identifier,
	current_connection_count,
	available_memory_bytes,
	last_rejection_reason);
```

Примечания:

- После if/for/while — без пробела; внутри круглых скобок дополнительных пробелов нет.
- Вокруг операторов — пробелы.
- После каждой точки с запятой внутри скобок — пробел.
- Блоки if/else/for/while — с фигурными скобками, даже для одной инструкции. Для простого условия и простого действия можно без скобок, как в примере выше.
- Одна инструкция на строку, кроме уже написанных однострочных `if` с простым действием:
  их сохранять. Многострочные `if` не склеивать. Даже короткие функции раскрывать на несколько строк.
- Длина строки — до 120 символов. Длинные вызовы переносить как в примере.
- Логические этапы отделять одной пустой строкой. Комментарий размещать перед соответствующим кодом.

Эти примеры задают только оформление. Они не вводят новые API или правила именования.
Сохранять существующие имена и обязательные идентификаторы SDK.
Для других языков следовать их локальным правилам. Не переносить этот C++ стиль автоматически.
