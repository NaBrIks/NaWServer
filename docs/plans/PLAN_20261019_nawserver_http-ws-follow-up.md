# Оставшиеся задачи HTTP и WebSocket

Дата: 2026-10-19. Основание: текущий код `src/handler_ws.*`, `src/http/web_server.cpp`
и `src/handler_static.*`. Ниже только незавершённые задачи; это не разрешение на
изменение транспорта или прошивку устройства.

- [x] Сделать результат WS-отправки явным: `WebSocketSendResult` для клиента,
  `WebSocketBroadcastResult` для рассылки. Различаются очередь, закрытая сессия,
  параметры/размер, память и ошибка постановки. Принятие не означает доставку.
  Шаблоны поведения и проверки: [guide](../readme_static_ws_ru.md).
- [ ] Завершить WS lifecycle: остановить производителей, учесть задания HTTPD,
  дождаться их завершения и только затем разрешить уничтожение endpoint/server.
  Проверить disconnect, повторное использование socket и stop/restart при
  ожидающих отправках. При переделке рассмотреть владение клиентами внутри endpoint
  вместо удаления клиента из собственного callback.
- [ ] Реализовать выбранные пределы транспорта: отдельно лимит TCP-соединений и
  WS-клиентов, настраиваемый pending limit, закрытие сессии при индивидуальном
  переполнении/зависании, ограниченное ожидание отправки и общий deadline.
  Не добавлять replay, QoS или неограниченные очереди.
- [ ] Проверить эти изменения на C3: обычный HTTP одновременно с WS, reconnect,
  переполнение, ошибки очереди/памяти и остановка под нагрузкой. Проверки писать
  под конкретные контракты и отказы; сборка сама по себе runtime не подтверждает.
- [x] Добавить явный MIME в плоские static text/binary handlers. Text сохраняет
  `text/html`, binary по умолчанию `application/octet-stream`; gzip отдельно.
  Host-проверка реализована; аппаратная регрессия C3 остаётся в пункте выше.

Авторизованный WS остаётся неподдерживаемым до отдельной реализации и проверки
отказа перед handshake. HTTP pipeline не защищает native WS upgrade. Другие SoC,
TLS, хранилища пользователей и файловые providers в эту очередь не включены.
