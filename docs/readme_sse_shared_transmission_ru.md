# SSE в общей очереди передачи

Дата: 2026-11-02. При включённой `TcpOptions.transmission.enabled` SSE использует
общую очередь TCP непосредственно. При выключенной опции сохраняется прежняя
очередь `FrameSet` и порционная отправка через `Stream::write`.

## Данные и память

В shared-режиме `Sessions` содержит метаданные: token/generation, порядок,
размеры событий, счётчики, сроки и причину закрытия. По клиентам не выделяются
`FrameSet` и payload через отдельный SSE MemoryManager, даже если
`initial_clients` задан больше нуля. `bufferMemoryStats` и managed SSE payload
stats поэтому показывают ноль. Реальные блоки и расходы учитываются общим
`transmissionStats`, фиксированные метаданные и task stacks остаются отдельно.

`publish` копирует готовый `Frame` один раз в выданный общий блок и публикует
полный кадр. Прежнего копирования из per-client FrameSet в 256-байтовый scratch,
а затем ещё раз в общий TX-блок нет. Размер общего блока должен позволять
поместить целый SSE Frame. Если полного блока нет, возвращается GlobalFull;
частичное событие в очередь не публикуется.

Очередь и лимиты остаются конечными. `pending`, `bytes_per_client`, `total_bytes`
ограничивают событие до публикации в общий пул. Индивидуальное превышение
инициирует Overflow-close; общий недостаток места даёт GlobalFull. Удаление или
слияние событий автоматически не включается.

## Передача владения

Во время reserve HTTP-preface записывается непосредственно в filling lease
общей очереди. До успешного activate и завершения HTTP callback lease не
публикуется. Rollback освобождает его и не отправляет ни одного байта.

SSE worker публикует заголовок после callbackComplete. До этого `publish`
возвращает существующий неблокирующий результат Busy; приложение должно
повторить публикацию из своего producer/poll после возврата HTTP handler.
Нельзя ожидать освобождения этого gate циклом внутри самого HTTP callback.

`Stream` предоставляет необязательные capability/acquire/status методы.
Native HTTPD, Windows/memory SSE streams без этой возможности продолжают
использовать прежний путь. Подготовка кадра в shared-режиме не передаёт владение
HTTP Request/Response/Next фоновой задаче.

## Завершение и сроки

Один поток SSE единолично ставит данные своего socket lifetime в очередь.
Оставшиеся байты общей очереди сопоставляются с метаданными кадров. Счётчик
sent_frames увеличивается после полного принятия события native TCP-стеком,
а не сразу после помещения в очередь. Это по-прежнему не ACK браузера.
Ошибочная/исчезнувшая очередь отмечается как Disconnected, а не как успешная
передача всех оставшихся событий.

Heartbeat, stall и transfer deadlines обслуживаются SSE state machine.
Если heartbeat не удаётся поставить в общий пул, ограничивается время ожидания
его блока; бесконечного удержания подписки из-за этой ситуации нет.
Остановка и retained-close сохраняют прежний контракт явной повторной очистки.
Заполненный lease заголовка отменяется до окончательного закрытия сокета.

`close` является неблокирующей операцией и может вернуть false при Busy metadata
lock. Это не доказательство, что подписка уже закрыта. Вызывающий повторяет
операцию ограниченно; проверка завершения выполняется по active/completions.

## Проверки

- Linux `sse_direct_session`: отсутствие legacy payload allocations даже с
  `initial_clients=2`, частичный native progress, точные completion counters,
  heartbeat, stall, транспортная ошибка, stale token, rollback и restart.
- Linux `tcp_websocket_worker`: два WS, 160 КиБ HTTP и SSE вместе, с проверкой
  нулевого отдельного SSE payload расхода и точного содержимого событий.
- Legacy `memory_sse`, `tcp_sse`, `tcp_sse_pending`, `tcp_sse_fatal_retained`
  прошли профильные регрессии после изменения.

Аппаратные результаты и Windows-проверки учитываются общим отчётом приёмки.
