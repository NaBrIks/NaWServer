# Требования к прикладному CBOR

Указание владельца от 20.10.2026: CBOR выбран для компактного бинарного обмена
с именованными полями и сохранением типов, а не для схемы числовых ID.

1. Ключи map — непосредственно UTF-8 имена полей: `"board_label"`, `"v"`,
   `"data"`. Числовая подстановка имён запрещена. Не создавать cbor-keys.json,
   сгенерированные таблицы ID, словари имён или эквивалентный обязательный реестр.
2. Значения передавать нативными CBOR типами: числа, boolean, null, UTF-8 строки,
   byte strings, массивы и вложенные map. Не применять JSON промежуточно,
   base64 для бинарных данных или строковое представление чисел ради кодека.
3. Неизвестное валидное имя не является ошибкой кодека. Новые поля не требуют
   регистрации. Получатель сохраняет их либо игнорирует на уровне конкретной
   команды. Валидация обязательных полей и их типов принадлежит обработчику API.
4. Имена известных полей и единицы измерения — прикладной контракт. Размеры
   строк/контейнеров и чисел содержит сама CBOR структура; DTO и проверки
   команд не заменяют имена ID-номерами.
5. Сохранять uint64 без потери точности, double и произвольные bytes с NUL.
   Отклонять некорректный UTF-8, дубликаты map-ключей, остаток после сообщения,
   числовые map-ключи, теги, неопределённые контейнеры и NaN/Infinity.
6. Сохранять явные ограничения ресурсов. Frontend/.NET: до 65536 байт при
   чтении, глубина 12, map до 128 полей, массив до 256 элементов. HTTP/WS
   команды устройства: до 4096 байт, map до 16 полей, имя до 64 UTF-8 байт,
   массив до 32 элементов, глубина до 4. Выходные буферы остаются ограниченными;
   переполнение возвращает ошибку, а не обрезанный пакет.
7. Один формат во frontend, эмуляторе, обеих прошивках и тестах. Проверять
   межъязыковой обмен и фактические ключи CBOR, а не только преобразованные DTO.

Это несовместимое изменение прежнего числового формата. Совместимый fallback
не вводится: frontend и firmware обновляются вместе. URL `/api/v2`, поле `v=2`
и прикладные операции сохранены; числовая таблица старой реализации удалена.
SSE остаётся отдельным текстовым потоком JSON, предусмотренным SSE API.
