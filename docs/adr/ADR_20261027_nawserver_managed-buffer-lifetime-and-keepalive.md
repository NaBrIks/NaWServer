# 2026-10-27 — начальные и динамические буферы, keep-alive

Статус: принято по прямому поручению владельца 27.10.2026.

## Причина

Полный начальный резерв всех HTTP jobs и WS arenas занимал 128531 Б в тестовой
конфигурации. Основной сценарий МК — предсказуемая REST-автоматизация; посещение
страницы настроек не требует удерживать все возможные payload buffers постоянно.
Настройки публичной библиотеки должны оставаться независимыми от демо/ESP32.

## Решение

Небольшой переносимый менеджер поверх существующего byte ledger и allocator:
`initial/maximum/block_bytes`, move-only блок, ранняя readiness и причина отказа.
Начальные блоки удерживаются, дополнительные выделяются фактического размера и
освобождаются при возврате. Квоты admission остаются независимой статической
политикой. Физический HTTP-резерв основного ключа включается отдельным флагом.
Bodyless HTTP не получает body, WS/SSE выделяются при подключении. Дескрипторы и
ограниченный ingress сохраняются для раннего короткого503 без новых выделений.

ESP-IDF placement/probe остаются за BufferAllocator; Win/Linux используют тот же
контракт с обычным allocator или заданным приложением. Минимум свободной памяти
относится к выбранной heap, не ко всем SDK-задачам. Фиксированный готовый блок
повторно используется без попытки выделения даже при сработавшем пороге.

Последовательный HTTP/1.1 keep-alive опционален и ограничен числом idle sockets,
простоем и числом запросов. Рабочие буферы и HTTP permit возвращаются между
запросами, ключ/квоты проверяются снова. Никаких повторно входящих callbacks.
Move-owned response позволяет не копировать уже владеющий блок второй раз;
неизменяемый flash body и безопасная копия временных данных остаются отдельными
явными контрактами. Память и сокеты SDK не становятся zero-copy автоматически.

## Последствия

Ни policy, ни API-резерв не обязательны для managed buffers/keep-alive. Компактный
scheduler пока исключается старым compile-time флагом TCP_ADMISSION; при
выключении кода соответствующие функции возвращают Unsupported. Legacy путь
сохраняется при выключенных опциях. Полный HTTP pipeline не входит в эту работу.
Idle sockets добавляют расход lwIP/ОС и должны входить в общий socket budget.
Динамика уменьшает простой резерв, но возможны allocator overhead/фрагментация;
начальный минимум и выбранная heap остаются настройками приложения.

Изменяет прежнее полное стартовое резервирование и close-only ограничение
управляемого TCP пути. Не отменяет ownership, stop/cleanup и transport границы
предыдущих ADR. Проверки и ограничения —
[датированный отчёт](../readme_20261027_memory_manager_keepalive_ru.md).
