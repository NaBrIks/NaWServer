# Тело HTTP-запроса: raw и явное копирование

Ядро хранит тело как байты, независимо от JSON, CBOR, form и других форматов.
Транспорт пока читает тело целиком до dispatch/pipeline, максимум 4096 байт.
Авторизация до чтения тела и потоковые загрузки — отдельный будущий этап.

## Без копирования

```cpp
const NaWServer::ByteView bytes = request.body();
const uint8_t *data = bytes.data();
const size_t length = bytes.size();
// bytes.empty() доступен; нулевые байты являются обычными данными.
```

`body()` не выделяет память, не копирует и не декодирует данные. Размер — число
считанных байтов, а не результат strlen. Для пустого тела указатель может быть nullptr;
ориентироваться на size()/empty(), не разыменовывать указатель пустого представления.

Память принадлежит запросу и действительна только во время текущего HTTP callback.
Не сохранять представление, его указатель или ссылку в задаче/очереди/глобальном объекте.
`ByteView` не раскрывает внутренний контейнер и не разрешает изменять данные.

## Копирование в выбранную память

```cpp
using NaWServer::BodyCopyResult;

uint8_t own[128];
auto result = request.copyBodyTo(own, sizeof(own)); // pointer + capacity
result = request.copyBodyTo(own);                  // C array: capacity выводится

std::array<uint8_t, 128> fixed;
result = request.copyBodyTo(fixed);

std::vector<uint8_t> dynamic;
dynamic.reserve(128); // необязательно; можно повторно использовать capacity
result = request.copyBodyTo(dynamic);

if (result != BodyCopyResult::Ok) {
    // Прикладная обработка ошибки.
}
```

Все перегрузки принимают байты `uint8_t`. Вариант с указателем подходит для памяти
на стеке, статического массива, пула и отдельно выделенного буфера. Источник один;
фасады фиксированных контейнеров используют общий механизм копирования.

| Результат | Значение |
|---|---|
| `Ok` | Скопировано ровно request.body().size() байт |
| `BufferTooSmall` | Ёмкость фиксированного назначения меньше тела; запись не выполнялась |
| `InvalidDestination` | Непустое тело, достаточная заявленная ёмкость, но destination == nullptr |

Проверка ёмкости идёт раньше проверки указателя. nullptr с нулевой ёмкостью допустим
для пустого тела. Хвост фиксированного буфера после скопированных байтов не изменяется;
терминатор NUL не добавляется. Для дальнейшей работы нужны и буфер, и длина тела.

`std::vector` получает точный размер тела; существующая capacity переиспользуется,
если её хватает. Пустое тело очищает размер, сохраняя capacity. Дополнительное
выделение памяти возможно: ошибка выделения подчиняется поведению std::vector и
настройкам toolchain. `BodyCopyResult` не обещает восстанавливаемую обработку OOM.
Для заранее ограниченной памяти использовать pointer/array/pool.

Копия принадлежит приложению и не зависит от уничтожения запроса. Но если копия
находится в локальном массиве обработчика, её срок жизни тоже ограничен callback.
В другую задачу передавать пакет по значению либо явно передавать владение буфером
из пула/контейнером. Копирование само по себе не освобождает HTTPD: нужно поставить
работу в ограниченную очередь, отправить ответ и вернуться из callback.

## Форматы и хранение

API не включает CBOR/JSON codecs и автоматическое преобразование в структуры.
Приложение выбирает библиотеку, проверяет Content-Type, формат и диапазоны значений.
После быстрого разбора можно передать задаче готовую структуру с числами вместо тела.

Внутренний `RequestBody` владеет `std::vector<uint8_t>`; передача от backend выполняется
перемещением, а `ByteView` не зависит от этого выбора. Прежний `std::string` хранения
заменён. `arg()` остаётся историческим query/form API: разбор по запросу может создавать
временный текстовый буфер. Он не нужен для raw/copy и не подходит для бинарного тела.
Проверка Content-Type перед form-разбором пока не добавлена — не применять arg() к
произвольному бинарному запросу. Старые transport ограничения этим API не исправляются.

## Проверки

- `tests/request_body_test.cpp`: 30 проверок binary/NUL, exact/overflow/null/empty,
  целостности назначения при отказе, независимости копий и переиспользования vector.
- `examples/minimal`: защищённый POST `/private/body`, открытые fixtures test/test-only.
  Заголовок `X-Body-Copy`: raw, pointer, c-array, array, vector. Fixed назначения имеют
  64 байта и возвращают 413 при превышении; raw/vector проверяются до 4096 байт.
- `tools/smoke`: проверяет точное совпадение байтов и MIME, все режимы, отказы при
  переполнении, запрет без авторизации и последующую работоспособность HTTP/WS.

Тестовый маршрут относится к minimal, не к ядру и не к продуктовым маршрутам showcase.
Результаты сборки и физического прогона указываются отдельно в отчёте этапа.
