# Распределение RAM в демках — 27.10.2026

Верхний индикатор RAM содержит тонкую цветную полоску без дополнительных
подписей. Она суммирует учтённые регионы текущего устройства. На INFO после
исходного графика свободной RAM добавлена низкая панель с вертикальными
столбиками. RAM/PSRAM стоят **сбоку**, объём под названием; сверху/снизу текста
нет. Столбики48×108 px. Исходный график, его шкала и сбор истории не менялись.
На узком экране панель имеет общую горизонтальную прокрутку.

| Цветовая категория | Что измеряется |
|---|---|
| Наша статика | Реальные linker-границы data/bss/common/legacy_bss/DRAM_ATTR компонентов main и NaWServer |
| Прочая статика | Остальная учтённая статика RAM текущего образа |
| Наши буферы | Живые payload bytes выделений ESP-IDF buffer allocator NaWServer; размещение определяется адресом, не предпочтением policy |
| Прочая динамика | Остальная занятая heap, включая SDK/библиотеки/стеки, неучтённые выделения и расходы allocator |
| Свободно | Текущий `heap_caps_get_free_size` для соответствующего региона |

Это обзор **RAM для данных**, а не физической ёмкости чипа: heap плюс учтённые
секции данных. IRAM, RTC, ROM, flash, PSRAM-отображения кода/rodata и недоступные
аппаратные резервы не добавляются. Поэтому объём столбика internal больше heap
на прежнем графике, но меньше паспортного SRAM чипа. DMA отдельно не суммируется.

Опциональный `summary.data.memory_usage[]` передаётся существующим CBOR HTTP/WS;
дополнительного периодического HTTP-запроса нет. Каждый регион содержит id,
total_bytes и пять категорий. Сумма категорий равна total_bytes. Свободная память
и counters снимаются во время работы; конкурентные выделения могут происходить
между чтениями, это не глобально остановленный снимок всех задач.

Лёгкий SDK helper `espIdfBufferUsage()` считает успешные payload allocations и
release по реальному адресу internal/PSRAM. Два атомарных счётчика, без таблицы
адресов и глобальных heap hooks; тяжёлая трассировка SDK не включается.
Padding/control allocations не объявляются нашими payload: остаются в прочей
динамике. Это не точная атрибуция каждого malloc по владельцу.

Для прошивок/host-источников без memory_usage остаются известное свободное место
и серое «Без разбивки»; отсутствующие категории обозначены прочерком, не нулём.
Информация о границах и способах подсчёта доступна через ⓘ этой панели.
