## Результат и границы

Публичный менеджер не знает о LCD/демо/основном API: начальные блоки, максимум,
предел байтов, allocator и остаток выбранной heap. Общий код переносим на
Windows/Linux; ESP placement/probe остаются в ESP-IDF helper. Admission отдельно
назначает квоты, физический API-резерв отдельно включается флагом. Подробный
[контракт и настройки](readme_buffer_memory_ru.md),
[решение](adr/ADR_20261027_nawserver_managed-buffer-lifetime-and-keepalive.md).

28951 Б — учтённые массивы/буферы TCP, **не вся RAM сервера**. В них:6144 Б
общих начальных HTTP metadata/response,10240 Б основного резерва,6144 Б ingress,
6423 Б остальных учтённых таблиц/дескрипторов. Native sockets, lwIP/Wi-Fi,
allocator overhead, control objects, стеки, LCD и JSON/MCP workspace отдельно.
Отключение API-резерва не отключает логическую квоту; без физического резерва
нельзя гарантировать выделение при общем исчерпании heap.

### Реальный предел байтов, а не только квот

8 незавершённых POST по4096 Б,4 на каждую из2 общих идентичностей. Header и1 байт
тела отправлены; редкие дополнительные байты удерживают запросы только на время
короткой проверки. После неё соединения намеренно отменяются. Завершения этих
неполных запросов не ожидаются и не считаются HTTP timeout. Основной API работает
параллельно; ни прошивки, ни SDK heap искусственно не истощаются.

При отказе header/response allocation короткий503 использует уже имеющуюся

## Практические ограничения

Это короткие функциональные/нагрузочные проверки, не длительный soak и не
повтор старого агрессивного reload. Keep-alive последовательный HTTP/1.1,
без полного pipeline. Native HTTPD сохраняет собственную реализацию.
Начальный минимум не статический `.bss`: это удерживаемые блоки выбранного
allocator. Максимум слотов — потолок, а не гарантия при нехватке byte/heap budget.
Гарантии основной системы ограничены её настроенными размерами/квотами,
скоростью обработчика и доступностью сети. При заполнении **всех** ingress/SYN/
native sockets возможен TCP close, до ключа/HTTP503 дело ещё не дошло.

Снижение TCP ledger не означает исчезновение allocator overhead/фрагментации.
После каждого ответа динамика освобождается, но ОС/lwIP может удерживать свои
состояния. Move-owned/immutable body устраняют лишнюю копию в нашем scheduler;
копии временных прикладных данных и SDK сохраняются там, где нужны для владения.
SDK `min_free_bytes` суммирует исторические минимумы heap regions и не равен
минимуму одновременно свободной всей internal RAM. В таблицах sampled free и
SDK historical minimum всегда отмечены отдельно.
