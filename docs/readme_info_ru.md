# INFO: компактная история и паспорт устройства

Уточнение владельца 20.10.2026: обычные отдельные графики CPU/RAM на INFO
восстановлены. Новый компактный график находится только справа над таблицей
задач и сохраняется при переключении страниц. Это один SVG с общей сеткой и
временем 60 секунд: CPU0 — красный, CPU1 — оранжевый, MEM — синий. На
одноядерной плате показываются CPU и MEM. Подписей осей нет; легенда совпадает
по цветам с линиями. CPU нормирован 0–100% по каждому ядру, MEM — свободная RAM
в процентах ёмкости своего пула. Абсолютная RAM остаётся в общей строке и INFO.

Высота компактного графика равна трём фактическим строкам таблицы задач:
ResizeObserver измеряет строку после рендера и обновляет высоту. В эмуляторе
получено 74.25 px / 24.75 px. График не прокручивается вместе со строками.
S3 уже передаёт core_busy_pct[0/1], рассчитанные из отдельных idle runtime
counters. Frontend хранит ограниченную историю каждого ядра и сбрасывает её
при смене Boot ID. Ядро HTTP/WS/SSE и прошивки не меняются в этой UI-проверке.

Общий frontend показывает необязательное `info.details`: группы именованных
полей с нативными строками, числами, boolean и null. Имена передаются в CBOR
непосредственно. Старые приложения без details показывают прежний краткий
паспорт. Общие компоненты и стили не копируются в отдельные демки.

Общий сборщик `examples/common/device_details.hpp` подключён к C3, S3 и C6.
Он не входит в библиотеку HTTP/WS/SSE. Все демки используют один формат
`info.details`; индивидуальный callback записывает группу `board`.

Общие details содержат:

- Оборудование: чип, архитектура, частоты CPU/кварца/APB, ревизия, ядра,
  Wi-Fi 2.4/6, Bluetooth LE/Classic, IEEE802.15.4, USB, HP/LP SRAM.
- Flash/RAM: физическая flash и JEDEC ID, встроенная flash, пулы internal/DMA,
  PSRAM и текущий раздел приложения. DMA-пул пересекается с internal, их нельзя
  суммировать. IDF 5.4 на C6 не выставляет CHIP_FEATURE_EMB_FLASH; наличие
  flash в корпусе задаётся спецификацией этой платы FH4, а не отсутствием бита.
- MAC: заводской/custom eFuse, base, STA, SoftAP, Bluetooth, Ethernet и EUI-64.
  Производные адреса не означают, что соответствующий интерфейс запущен;
  Ethernet MAC не доказывает наличие PHY. Неподдерживаемый/отсутствующий адрес — null.
- Сеть: подключение, режим, IPv4/маска/шлюз, SSID/BSSID, канал, RSSI и auth mode.
  Подключение и RSSI обновляются из summary, остальные поля читаются с info.
- Плата: контроллер/разрешение LCD, готовность SPI, отдельный непроверенный
  визуальный статус, подсветка, RGB GPIO/порядок/драйвер, SD-slot/mount, touch,
  запуск BLE. Физическое наличие отделено от текущего запуска функции.
- Сборка: проект, версия, ESP-IDF, дата/время, secure version, полный ELF SHA256,
  reset reason и Boot ID. Полный SHA берётся из 32 байтов app descriptor:
  штатный esp_app_get_elf_sha256 может возвращать только настроенный префикс.

Плотные таблицы идут в 3 или 4 колонки без растяжения коротких блоков до высоты
соседних. В узком контейнере — одна колонка; таблица MAC сохраняет минимальную
ширину и горизонтальную прокрутку. Полный EUI-64 виден, длинный SHA доступен
в подсказке. Числа выровнены вправо, MAC моноширинные.

Проверки: общий vue-tsc/Vite для C3/S3/C6, npm test, C6 hardware smoke,
реальный Chromium с HTTP/WS/SSE, измерением высот и проверкой отсутствия
обрезки EUI-64. Только C6 перешивается в этой задаче; C3/S3 на том этапе проверялись сборкой
frontend. Теперь расширенный payload реализован во всех трёх демках;
новые проверки описаны ниже.

Результат проверки после уточнения цветов: CPU0 rgb(192,57,43), CPU1

## Общие характеристики C3 / S3 / C6, 20.10.2026

Общий модуль собирает пять групп: hardware, flash_memory, mac_addresses,
network, build. Модель/архитектура и штатная SRAM выбираются по target SDK;
частоты, ревизия, число ядер, features, физическая flash/JEDEC, heap/PSRAM,
MAC, состояние Wi-Fi, адреса и app descriptor читаются через ESP-IDF.
LP SRAM у C3/S3 обозначает RTC SRAM; эти ёмкости не являются свободным heap.
Без Wi-Fi/flash/MAC данные представлены null. EUI-64 на C3/S3 — null.
Режим Wi-Fi читается из SDK, а не задан константой STA. SSID ограничен размером
буфера SDK. DMA/internal heap пересекаются, их нельзя суммировать.

Индивидуальные main/device_details.cpp добавляют группу board:
- C3 showcase: конфигурация внешней ленты 10 WS2812/GPIO2/GRB, текущий RMT/SPI,
  готовность драйвера ленты и индикатора. Наличие подключённой внешней ленты
  программно не определяется; RGB ready означает успешную инициализацию драйвера.
- S3 touch_lcd7: RGB565 800×480, GT911, LVGL, два framebuffer, готовность LCD,
  состояние подсветки и конфигурация внешней ленты GPIO6. LCD ready не закрывает
  известный визуальный дефект полосы на дисплее.
- C6: прежние ST7789T/SPI, GPIO8/RGB/RMT, SD, отсутствие touch, непроверенный
  визуальный статус. Исключение embedded flash для корпуса FH4 осталось здесь.

Одинаковые подписи полей и таблицы находятся только в общем frontend.
Подключение новой платы не требует копирования UI или общего сбора характеристик.

Проверка этой версии:
- Полные firmware-сборки C3/C6/S3 PASS; S3 использует проверенный локальный
  PLATFORMIO_CORE_DIR, а не глобальный каталог пользователя. C3 RAM 61848 B,
  flash sections 1085376 B; C6 RAM 72608 B / flash 1138235 B;
  S3 RAM 72712 B / flash 1356368 B.
- Общий vue-tsc/Vite для всех трёх профилей и npm test: 10/10 PASS.
- examples/common/tests/Test-DeviceDetails.ps1 компилирует реальные проектные
  device_details.cpp и общий сборщик с подменой SDK (не физическое устройство).
  Проверены definite CBOR-контейнеры, типы, периферия каждого target, отсутствующие
  данные, длинный SSID и отказ при переполнении. Размеры details: C3 929–1145 B,
  S3 1061–1277 B, C6 1041–1280 B. Это размеры details, не полного ответа info.
- frontend/tools/verify-device-details.mjs подставляет созданные C++ тестом CBOR
  в локальный preview. Chromium PASS для C3/S3/C6: шесть групп, четыре колонки,
  индивидуальные поля, отсутствие ошибок JS. Скриншоты просмотрены.
- verify-info-preview.mjs: прежние графики INFO, три строки компактного графика,
  цвета CPU0/CPU1/MEM, три/четыре колонки и независимая прокрутка PASS.

Платы этой версией не прошивались. Native/browser проверки используют тестовые
значения SDK, аппаратное чтение новых полей на C3/S3 ещё не проверено.

Повтор сборки S3 из examples/touch_lcd7:

```powershell
$env:PLATFORMIO_CORE_DIR=(Resolve-Path './local/pio-core').Path
& %USERPROFILE%\.platformio\penv\Scripts\pio.exe run -e s3 -j8
```

Native тест из корня: ./examples/common/tests/Test-DeviceDetails.ps1.
Он использует существующий local/host-tools/zig-x86_64-windows-0.14.1/zig.exe;
путь можно передать через -ZigPath. Зависимости тест сам не устанавливает.
Браузерный тест требует ранее запущенный preview 127.0.0.1:8792 и доступный
Playwright Chromium (при необходимости C6_BROWSER_EXECUTABLE).

## Чистая пересборка на PlatformIO Core 6.2.0, 20.10.2026

Локально подтверждён Core 6.2.0 вместо ранее записанного 6.1.x.
Запуск через %USERPROFILE%\.platformio\penv\Scripts\pio.exe с
PLATFORMIO_CORE_DIR=<repo>/local/pio-core.
Core обновил tool-scons 4.40801.0 → 4.41101.0 (SCons 4.11.1).
Первые параллельные clean S3/C6 попали на замену SCons и завершились ошибкой
импорта; после завершения установки повторные clean/build прошли.
Espressif32 6.10.0, ESP-IDF 5.4.0 и GCC 14.2.0+20241119 сохранены.

Пересобран общий frontend всех трёх профилей, ресурсы упакованы в firmware.
npm test: 10/10 PASS. Полные clean/build C3, S3, C6: SUCCESS.
Размеры firmware.bin: C3 1085776 B, S3 1356768 B, C6 1138624 B.
SHA-256 и результаты сохранены в ignored local/pio620-rebuild-results.json;
логи — examples/<project>/local/pio620-build.log.
На физические платы эта пересборка не записывалась.

## Развёртывание на C6 и S3 после пересборки, 20.10.2026

По прямому запросу владельца записаны принятые образы Core 6.2.0.
Перед записью заново проверены COM13/C6/MAC DEVICE-MAC и
COM12/S3/MAC DEVICE-MAC, SHA-256 образов и текущие таблицы разделов.
Записаны только приложения: C6 [0x10000,0x125fc0), S3 [0x10000,0x15b3e0).
Hash verification PASS; NVS и таблицы разделов не перезаписывались.
Полные SHA и диапазоны: examples/<project>/local/pio620-deploy.json.

Первые сетевые проверки не прошли: Wi-Fi ПК был отключён, маршрут уходил в
Mihomo. После включения Wi-Fi владельцем обе платы доступны по прежним IP:
C6 http://192.0.2.1, S3 http://192.0.2.2.
C6 hardware smoke PASS: identity/details, память/задачи, SHA 5 ресурсов,
бинарный WS echo и SSE. S3 protocol/asset smoke: 27/27 PASS, info 2396 B,
SHA 7 ресурсов, LCD ready, CBOR validation, WS и SSE.
Реальный Chromium для обеих плат: шесть INFO-групп, индивидуальные GPIO,
HTTP/WS/SSE онлайн, два графических ряда CPU/MEM у C6 и три CPU0/CPU1/MEM
у S3, отсутствие JS errors. Полные ELF SHA прочитаны из нового info.details.
Это короткая проверка; изображение повреждённого C6 LCD и известный дефект
полосы S3 ею не подтверждаются и не закрываются.

## 27.10.2026 — цветное распределение реальной RAM

Верхний RAM sparkline заменён тонкой полоской без подписей; график свободной
RAM на INFO сохранён. После него — невысокая панель с вертикальными столбиками
48×108 px. RAM/PSRAM сбоку, объём под названием; сверху/снизу надписей нет.
Состав: наша/прочая статика, живые наши буферы, прочая динамика, свободно.
Показана только учтённая RAM для данных, не вся паспортная SRAM/PSRAM.
